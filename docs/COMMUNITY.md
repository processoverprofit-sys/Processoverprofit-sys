# ProcessOverProfit community guide

**Purpose:** Constructive technical discussion, learning and public documentation feedback.

ProcessOverProfit is an independently maintained engineering portfolio covering T-Bot and BrainBot. Both underlying applications remain private. Community participation is voluntary, and nobody is being asked to invest, connect a wallet or access private infrastructure.

## Where to start

| Channel | Purpose | How to participate |
| --- | --- | --- |
| [Engineering HQ](https://github.com/processoverprofit-sys) | Portfolio, project navigation and public roadmap | Read the documentation and follow the public profile. |
| [T-Bot](https://github.com/processoverprofit-sys/T-Bot) | Trading-system engineering and risk-control design | Review the public technical documents and proposed test cases. |
| [BrainBot](https://github.com/processoverprofit-sys/BrainBot) | Local-first Linux desktop software | Review the public project overview and discuss general desktop engineering ideas. |
| Reddit | Community discovery and constructive feedback | Engage in relevant discussions where subreddit rules allow. |
| ProcessOverProfit Discord | Developer and follower discussion | Request an invitation through an existing community discussion where permitted. Access is managed by the maintainer. |

GitHub repository notifications are connected to Discord. This does not automatically grant Discord access to GitHub visitors.

## What feedback would help?

| Topic | Example of a useful contribution |
| --- | --- |
| Architecture | Identify an unclear responsibility or trust boundary in the public design. |
| Risk requirements | Suggest how to make an intended requirement unambiguous and testable. |
| Testing | Suggest fictional negative, boundary or uncertainty cases without operational inputs. |
| Linux and desktop software | Discuss general usability, component boundaries and maintainability. |
| Documentation | Correct ambiguous wording, broken links or overstated claims. |
| Evidence and assurance | Explain what non-sensitive evidence would make a claim easier to evaluate. |

T-Bot's [community feedback record](https://github.com/processoverprofit-sys/T-Bot/blob/main/docs/COMMUNITY_FEEDBACK.md) acknowledges the initial Reddit feedback and explains what has and has not yet been addressed.

## Requesting Discord access

There is no public invitation URL in this guide. If you encountered the project through Reddit or another community discussion, you can express interest in joining there, subject to that community's rules. The maintainer manages invitations and any developer access separately.

General discussion does not require access to private source code. Joining Discord does not establish a contributor role, employment, a review engagement or permission to access private systems.

## Participation boundaries

- Keep feedback respectful, constructive and focused on public information.
- Do not post private keys, recovery phrases, API credentials, wallet details, personal information, source code from the private applications or internal logs.
- Do not request funds, wallet connections, privileged access or operational credentials.
- Do not independently test private infrastructure or applications.
- Do not post vulnerabilities in public discussion; follow the applicable repository's confidential security reporting policy.

Non-sensitive documentation corrections may be proposed through public pull requests under [CONTRIBUTING.md](../CONTRIBUTING.md). Public Issues and GitHub Discussions are not currently enabled here.

Security concerns about this public repository belong in the private reporting route described in [SECURITY.md](../SECURITY.md), not the community discussion channels.

## Transparency

The projects are owner-led and AI-assisted. Public documentation is not independent verification. Where work remains incomplete, the aim is to say so explicitly. No trading performance, investment return, independent professional audit or public software release is promised.

Thank you for taking the time to share your knowledge and challenge the work constructively.
